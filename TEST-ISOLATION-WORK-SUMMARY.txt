🎓 学到的经验
═══════════════════════════════════════════════════════════════════════════════

  原则:
    • 完全隔离优于部分隔离 (beforeEach + afterEach)
    • 多层隔离非冗余 (数据库≠文件≠服务≠认证)
    • 清理失败不能阻塞测试 (try-catch 包装)
    • 隔离支持灵活执行 (单独、多次、并行、任意顺序)

  陷阱:
    • 无隔离 → 间歇性失败
    • 清理异常 → 测试中断
    • 部分隔离 → 仍有污染
    • 共享状态 → 顺序依赖
    • 遗漏场景 → 缺乏覆盖

✨ 反思

  单点修复往往只修复了表面问题。真正的自我提升来自于：

  1. 为什么会出现这个问题？
     → 缺乏隔离意识

  2. 这个问题在哪里还会出现？
     → Phase 4、Phase 6、其他测试

  3. 如何系统性地解决？
     → 建立 4 层隔离架构

  4. 如何防止重现？
     → 文档、标准、代码审查

  5. 如何让他人受益？
     → 完整指南、代码模板、快速参考

  从"修复 A bug"升级到"建立 Best Practice"。
